## 1. 시작하기 — 로그인

관리자 계정(이메일 + 비밀번호)으로 로그인합니다.

- **접속 경로**: `/admin/login`
- **입력**: 이메일 · 비밀번호
- **로그인 가능 계정**: 운영자 권한 계정만 허용됩니다.
  운영자(2), 관리자(401), 통계운영자(402), 일반운영자(403), 접수설치(404), 외부운영자(405)
- 활성(`is_active=1`) 계정만 로그인할 수 있습니다.
- 이메일·비밀번호 오류 시 **동일한 실패 메시지**가 표시됩니다(계정 존재 여부 노출 방지).
- **로그아웃**: 상단 메뉴에서 로그아웃 → 세션 종료 후 로그인 화면으로 이동

로그인 후 좌측 사이드바에 16개 메뉴가 나타납니다.

## 2. 대시보드

플랫폼 전체 현황을 한눈에 보는 첫 화면입니다. (`/admin/dashboard`)

### 상단 KPI 카드 (5종)

| 카드 | 의미 |
|------|------|
| 총 광고수 | 전체 등록된 광고(캠페인) 건수 |
| 진행중 광고 | 상태가 '진행중(active)'인 캠페인 수 |
| 이달 신규 계약 | 이번 달 신규 계약 건수 및 총액(원) |
| 이달 매출 | 이번 달 입금 확인된 매출액(원) |
| 전체 잔액 | 충전액 − 소진(차감)액 |

### 차트

- **월별 신규 계약 건수** — 최근 6개월 막대 차트
- **월별 매출** — 최근 6개월 라인 차트 (Y축 단위: 만원)

## 3. 광고주 관리

광고주(병원 단위)를 등록·조회·수정하고 상태를 관리합니다. (`/admin/advertisers`)

### 목록 화면

- **검색·필터**: 병원명 검색 / 상태(전체·활성·정지·탈퇴) / 네트워크 유형(전체·일반·모병원·자병원)
- **주요 컬럼**: ID, 병원명(클릭 시 상세), 담당자, 연락처, 네트워크, 모병원, 상태, 등록일
- **버튼**: `+ 광고주 등록`, 행별 `수정`

### 상세 화면

특정 광고주의 정보와 실적을 확인합니다.

- **KPI 카드**: 계약 총금액 / 잔여 충전금 / 진행중 캠페인 수
- **기본 정보**: 병원 ID, 사업자등록번호, 네트워크 유형, 모병원(자병원인 경우)
- **담당자 정보**: 담당자명, 이메일, 연락처, 연결된 포털 로그인 계정, 등록일
- **자병원 목록**: 모병원인 경우 소속 자병원 표시(클릭 시 이동)
- **계약 목록**: 계약 ID, 계약명, 결제방식(선불/후불), 등록일
- **버튼**: `수정`, `+ 수주계약 등록`(계약 관리로 이동, 병원 자동 연결)

### 등록 / 수정

| 항목 | 설명 |
|------|------|
| 병원 선택 | (등록 시) 등록된 병원 중 선택 → 병원명 자동 입력 |
| 병원명 * | 최대 255자 (수정 시 읽기전용) |
| 담당자명 / 연락처 / 이메일 / 사업자등록번호 | 담당자·병원 기본 정보 |
| 로그인 계정 연결 | 미연결 시 체크박스로 포털 로그인 계정 생성·연결 가능(로그인 이메일 + 비밀번호 8자 이상) |
| 네트워크 유형 * | 일반(0) / 네트워크 모병원(1) / 네트워크 자병원(2) |
| 모병원 | 네트워크 자병원일 때만 표시 — 활성 모병원 중 선택 |
| 상태 * | 활성(1) / 정지(2) / 탈퇴(3) |

> **계정 연결 규칙**: 한 로그인 계정은 하나의 광고주에만 연결됩니다. 이미 사용 중인 이메일로는 신규 계정을 만들 수 없습니다.

## 4. 병원 관리

병원 마스터 데이터와 진료과 매핑을 관리합니다. (`/admin/hospitals`)
광고주가 '병원 단위 실체'라면, 여기서는 병원 자체의 정보·진료과·공개 노출을 다룹니다.

### 목록 화면

- **검색·필터**: 병원명 / 상태(활성·비활성)
- **주요 컬럼**: ID, 병원명, 유형(일반·네트워크 모/자), 진료과(매핑 목록), 연락처, 상태, 등록일
- **관리 버튼**: 수정 / 삭제(소프트 삭제 — `is_deleted=1`, 상태 비활성 전환)

### 등록 / 수정

| 항목 | 설명 |
|------|------|
| 병원명 * | 최대 255자 |
| 유형 * | 일반(1) / 네트워크 모병원(2) / 네트워크 자병원(3) |
| 상태 * | 활성(active) / 비활성(inactive) |
| 연락처 / 주소 | 병원 연락처·주소 |
| 진료과 매핑 | 등록된 진료과를 체크박스로 다중 선택 |

> - 진료과가 없으면 먼저 **진료과 관리**에서 추가해야 합니다.
> - **활성 상태로 저장하면** 해당 병원의 공개 URL이 자동으로 IndexNow에 제출되어 검색엔진 색인이 요청됩니다(SEO).

## 5. 진료과 관리

병원에 매핑되는 진료과 코드 마스터를 관리합니다. (`/admin/departments`)

### 진료과 추가

| 항목 | 규칙 |
|------|------|
| 코드 * | snake_case (영소문자 시작, 영소문자·숫자·`_`), 최대 30자. 예: `plastic_surgery` |
| 표시명 * | 한글 진료과명, 최대 100자. 예: 성형외과 |
| 정렬 | 0 이상 정수(기본 0) |
| 활성 | 체크박스(기본 활성) |

### 진료과 목록

- 각 행에서 코드·표시명·정렬·활성을 **인라인 수정** 후 저장할 수 있습니다.
- 삭제 버튼에는 매핑된 병원 수가 `삭제(N)` 형태로 표시됩니다.
- **매핑된 병원이 1곳 이상이면 삭제 불가** → "비활성으로 변경하세요" 안내가 뜹니다.

## 6. 캠페인 관리

의료 광고 캠페인을 생성·수정하고 상태를 관리합니다. (`/admin/campaigns`)

### 목록 화면

- **검색·필터**: 상태 / 검수 상태 / 광고 타입 / 채널 / 키워드(캠페인명·병원명)
- **주요 컬럼**: ID, 캠페인명, 병원명, 광고 타입, 채널, 상태, 검수 상태, 광고 시작·종료일, DB 단가
- **버튼**: 캠페인 등록, 임시저장 목록, 행별 수정

### 등록 / 수정 폼

- **기본 정보**: 캠페인명 *, 병원 *(활성 병원), 광고 타입 *, 채널 *, 광고 기간 *, 노출 유형(이벤트·병원상세·전체)
- **광고 카피**: 상세문구(Tiptap 에디터) — 허용 태그로 제한.
  - **AI 추천** 버튼: 키워드·병원 유형·카테고리를 입력하면 **제목 후보 3개**와 상세 문구를 생성 → 제목 후보는 클릭으로 캠페인명에 적용
- **가격 정보(소비자 노출)**: 가격 유형(숫자/텍스트) — 숫자면 정상가·할인가, 텍스트면 안내 문구(예: "상담 후 결정")
- **광고 단가(과금)**: 광고 타입에 따라 필드가 달라집니다.
  - CPA → DB 단가 / CPM → CPM 단가(1,000회 노출당) / CPC → CPC 단가(클릭당) / 프로모션·옵션 → 과금 단가 없음
- **추가 정보**: 지역, 키워드(콤마 구분), 의료심의번호, 계약 ID, 카테고리
- **이미지**: 썸네일 1·2, 상세 이미지(다중). 수정 시 새 파일 업로드하면 교체됩니다.

### 상태 변경 (액션)

목록·상세에서 상태를 전환합니다. 변경 시 히스토리에 기록됩니다.

| 액션 | 전이 | 비고 |
|------|------|------|
| 승인(approve) | 검토중 → 진행중 | |
| 반려(reject) | 검토중 → 반려 | |
| 종료(end) | 진행중 → 종료 | 사유(메모) 필수 |
| 재검토(reopen) | 반려 → 검토중 | |

> 종료된 캠페인은 상태를 다시 변경할 수 없습니다.

### 히스토리 · 임시저장

- **히스토리**(`/campaigns/{id}/history`): 액션·상태변경·메모·처리자·일시를 페이지 단위로 조회
- **임시저장 목록**(`/campaigns/temp`): 저장만 하고 미제출한 캠페인을 불러오기

### 상태값

| 캠페인 상태 | 의미 | | 검수 상태 | 의미 |
|------|------|---|------|------|
| pending | 검토중 | | pending | 검수중 |
| active | 진행중 | | approved | 검수완료 |
| rejected | 반려 | | rejected | 검수반려 |
| ended | 종료 | | | |

## 7. 검수 관리

캠페인 등록·수정 요청을 검수해 승인/반려합니다. (`/admin/reviews`)
운영자가 광고 콘텐츠 변경을 최종 승인하는 관문이며, **AI 의료광고 심의 사전검사** 결과를 함께 확인합니다.

### 목록 화면

- **검색**: 키워드(캠페인명·병원명), 검수 대기 건수 표시
- **주요 컬럼**: ID, 캠페인명, 병원명, 캠페인 상태, 수정자, 수정 일시

### 상세 / 검수 화면

- **요청 유형**: 최초 등록 요청 vs 수정 요청
- **AI 의료광고 심의 사전검사**: 검사 상태 배지(대기중·안전·주의·위반 의심), 위반 플래그(규칙·심각도·문제 표현·사유·수정안), 모델명·검사 시각
  - `검사 결과 재요청` 버튼으로 재검사 가능
- **Before / After 비교**: 캠페인 항목·상세문구·썸네일·상세 이미지를 **현재(승인본) vs 변경 요청** 좌우 비교(변경 항목 표시)
- **검수 처리**: 메모(선택) 입력 후 `승인` 또는 `반려`

### 처리 결과

| 액션 | 결과 |
|------|------|
| 승인(approve) | 요청 콘텐츠가 실제 캠페인에 반영됨. 이미지 필드가 비어 있으면 기존 이미지 유지 |
| 반려(reject) | 요청 반려. 다른 대기 요청이 있으면 검수 상태는 계속 '검수중' 유지 |

### AI 심의 위험도

| 값 | 의미 |
|------|------|
| safe | 안전(위반 소지 없음) |
| warning | 주의 |
| violation | 위반 의심 |

## 8. 소재 관리

캠페인의 **이미지 소재**(썸네일·상세 이미지)만 별도로 교체 요청합니다. (`/admin/creatives`)

### 목록 화면

- **검색·필터**: 상태 / 소재 등록 여부 / 키워드(캠페인명·병원명)
- **주요 컬럼**: ID, 캠페인명, 병원명, 광고 유형, 상태, 썸네일1·2 등록 여부, 상세이미지 장수, 등록 일시

### 수정 화면

- 썸네일 1·2, 상세 이미지(행 추가·삭제 가능)를 URL 또는 파일명으로 입력하고 미리보기로 확인
- **저장하면 검수 대기 상태로 기록**되며, 실제 이미지는 **검수 승인 후** 반영됩니다(콘텐츠 텍스트는 기존 승인본 유지).

## 9. 이벤트 신청 DB

광고를 통해 유입된 **이벤트 신청(리드)** 을 상태별로 추적·처리합니다. CPA 과금의 기준이 되는 핵심 화면입니다. (`/admin/call-requests`)

### 목록 화면

- **검색·필터**: 병원 ID / 캠페인 ID / 상태 / 키워드(이름·연락처) / 정렬(최신순·전환점수순)
- **주요 컬럼**: ID, 신청자, 연락처, 병원명, 캠페인명, 상태, 전환점수(AI), 과금 여부, 단가, 확인일시, 신청일시
  - 전환점수: 70↑ 초록 · 40~70 주황 · 40 미만 회색

### 상세 화면

- **신청 정보**: 신청자·연락처·나이·성별·통화 가능 시간·디바이스·지역·유입 경로·CPA 단가·문의 내용·예약 일시
- **AI 분석**: 전환점수, 한 줄 요약, 다음 상담 액션
- **상태 변경**: 상태 드롭다운 → 예약(5) 선택 시 예약 일시 입력, `변경`
- **메모**: 최대 500자 등록/삭제. 메모 등록 시 AI 분석 큐에 적재됩니다.

### 상태값 & 환불 트리거

| 값 | 의미 | | 값 | 의미 |
|----|------|---|----|------|
| 1 | 미확인 | | 6 | 예약취소 |
| 2 | 부재중 | | 7 | 내원완료 |
| 3 | 취소 | | 8 | 중복 |
| 4 | 기타 | | 9 | 결번 |
| 5 | 예약 | | | |

> **환불 트리거 상태(3 취소 · 8 중복 · 9 결번)**: 광고주가 이 상태로 바꾸면 환불요청이 생성되고, **운영자가 처리하기 전까지 광고주의 추가 상태 변경이 잠깁니다.** → [환불요청 관리](#12-환불요청-관리)에서 처리합니다.

## 10. 계약 관리

병원별 **메인 계약**과 그 하위의 **수주계약**(실제 충전·상품 건)을 관리합니다. (`/admin/contracts`)

### 계약 구조

- **메인 계약**: 병원과의 기본 계약(결제방식 등)
- **수주계약(주문)**: 메인 계약 아래의 개별 광고 상품·충전 건. 입금 확인·세금계산서 발행 단위

### 화면 구성

- **메인 계약 목록**: 병원명·계약명·결제방식·수주건수·총 계약금액·계약일
- **메인 계약 상세**: 계약 정보 + 하위 수주계약 목록. `수주계약 추가` 버튼
- **수주계약 목록**(`/contracts/orders`): 병원·계약명·상품종류·금액·상태·입금일 (필터: 병원명·상태·상품종류)

### 수주계약 등록 / 수정

| 항목 | 설명 |
|------|------|
| 병원 ID · 병원명 * | 대상 병원 |
| 계약 유형 | 신규 / 재계약 |
| 계약 방식 * | CPA / CPM (수정 시 변경 불가) |
| 상품 종류 * | 이벤트·메인배너·이벤트존메인배너·CPM·기타 (수정 시 변경 불가) |
| 계약금액 * | 입금·세금계산서 발행 후에는 수정 불가 |
| 결제방식 | 선불 / 후불 (신규 등록 시) |
| 세금계산서 정보 | 담당자명·이메일·사업자번호(선택) |
| 에이전시 정보 | 대행사 유저 ID·담당 운영자·회사명·수수료율(선택) |

### 입금 확인

- 수주계약 상세에서 **입금 확인** 버튼(입금 미확인 + 상태 '정상'일 때만 노출)
- 확인 시 입금일이 기록되고 충전액이 잔액에 반영됩니다.

### 수주계약 상태값

| 값 | 의미 | | 값 | 의미 |
|----|------|---|----|------|
| 1 | 정상 | | 4 | 계약취소 |
| 2 | 발행환불 | | 5 | 계약환불 |
| 3 | 발행취소 | | 6 | 이월종료 |

## 11. 결제 관리

신용카드·가상계좌 결제 내역을 조회하고 환불을 처리합니다. (`/admin/payments`)

### 목록 화면

- **검색·필터**: 상태 / 병원명 / 기간
- **주요 컬럼**: ID, 병원명, 결제유형(가상계좌·신용카드), 금액, 결과코드, 상태, 등록일

### 상세 & 환불

- **결제 정보**: 결제 유형·금액·결과 코드·거래번호·승인 일시·승인 번호·금융사, (가상계좌라면) 계좌번호·만료일시
- **계약 정보**: 연결된 계약·수주계약
- **환불 내역**: 유형·금액·결과·거래번호·일시 + 누적 환불액·잔여액
- **환불 처리** 버튼(전액 환불 상태가 아닐 때):
  - 환불 유형(발행환불·계약환불) 선택
  - 환불 금액 입력(1 ~ 잔여 환불 가능액 = 결제금액 − 누적환불액)

### 상태값

| 값 | 의미 | | 값 | 의미 |
|----|------|---|----|------|
| pending | 입금대기 | | refunded | 환불 |
| paid | 결제완료 | | failed | 실패 |
| partial_refunded | 부분환불 | | | |

## 12. 환불요청 관리

광고주가 신청DB를 **취소·중복·결번**으로 바꾸면 생성되는 환불요청을 승인/거부합니다. (`/admin/refund-requests`)

### 목록 화면

- **필터**: 상태(전체·대기·승인·거부)
- **주요 컬럼**: 신청자, 캠페인/병원, 요청 유형(취소·중복·결번), 사유, 단가, 과금 여부, 상태, 요청일

### 처리

| 액션 | 결과 |
|------|------|
| 승인 | 환불요청을 '승인'으로. **과금된 건이면 차감액을 복원**(기타충전). 광고주의 상태 변경 잠금 해제 |
| 거부 | '거부'로. **거부 사유(1~500자) 필수**. 광고주에게 사유가 노출되고 상태 변경 잠금 해제(광고주가 다시 변경 가능) |

### 상태값

| 값 | 의미 |
|----|------|
| 1 | 대기 |
| 2 | 승인 |
| 3 | 거부 |

## 13. 후기 운영

이벤트·병원·접수 후기(리뷰)를 관리하고 신고를 처리합니다. (`/admin/boards`)

### 목록 화면

- **검색·필터**: 유형(이벤트·병원·접수) / 상태(정상·임시삭제·완전삭제) / 신고만 보기 / 의심 후기만(AI 신뢰점수 < 40) / 키워드(제목·작성자)
- **주요 컬럼**: ID, 유형, 제목, 작성자, 별점, 좋아요, 신고 수, AI 신뢰점수, 감성, 플래그, 상태, 작성일시

### 상세 & 액션

- **기본 정보 + 본문 + AI 신뢰성 분석(신뢰점수·감성·플래그·근거) + 신고 내역**
- 액션:

| 액션 | 결과 |
|------|------|
| AI 재분석 | 신뢰성 분석 큐에 적재(상태 '대기중') |
| 별점 집계 갱신 | 대상 요약 별점을 재계산 |
| 임시삭제 | `is_delete=1` (복구 가능) |
| 완전삭제 | `is_delete=2`, 삭제일 기록 |
| 복구 | 삭제 상태 해제 |

### 상태·분류값

- **삭제 상태**: 0 정상 / 1 임시삭제 / 2 완전삭제
- **AI 분석 상태**: 0 미분석 / 1 대기중 / 2 완료 / 3 실패
- **감성**: positive(긍정) / neutral(중립) / negative(부정)
- **플래그**: spam · fake · exaggeration(과장) · medical_overclaim(의학적 과장) · advertisement(광고성) · duplicate(중복)
- **신뢰점수**: 40 미만 의심(빨강) / 40~70 주황 / 70 이상 신뢰(초록)
